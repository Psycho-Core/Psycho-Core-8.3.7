 WHAT I CHECKED
===========================================================================
This zip ships with its own Dev/API_DIFFERENCE_REPORT.md, written when
this "Reforged + Modernized" core was assembled. It compares this core's
APIs (it calls them "Bfa") against the older core mod-psychobot was
originally written for ("Psycho"), and flags a long list of differences
in Player.h, Unit.h, Group.h, WorldSession.h, SpellMgr.h, etc. I went
through that report's flagged risk areas one by one and checked them
against what mod-psychobot actually uses:

1. WorldSession constructor used by PsychobotFactory.cpp (the 11-argument
   socketless-session constructor) - CONFIRMED PRESENT. This core already
   has a dedicated compatibility overload with a comment explicitly
   calling out mod-psychobot:
     "Psycho_Core / mod-psychobot compatibility overload. BfaCore's
      native constructor carries AuthFlags and Battle.net account name;
      socketless bot sessions do not need either, so delegate with safe
      defaults."
   Signature matches PsychobotFactory.cpp's call exactly. No changes
   needed.

2. S28 socketless bot session support (IsBot/SetBot/SetBotRemove/
   IsBotRemoving/BotLogin, null-socket guards in Update()) - all present
   in WorldSession.h/.cpp and CharacterHandler.cpp, same as the previous
   core. No changes needed.

3. Group.h "loot/roll" API differences (the API report listed ~20
   Group.h methods like GroupLoot, MasterLoot, Roll, SendLootRoll*, etc.
   as missing in this core) - mod-psychobot's PsychobotGroupMgr.cpp only
   uses ONE Group.h method from that area of the API:
   GetMemberFlags(ObjectGuid). I confirmed this core's Group.h still has
   it (uint8 GetMemberFlags(ObjectGuid) const), plus the
   MEMBER_FLAG_MAINTANK enum value it's combined with. None of the other
   ~20 flagged Group.h differences are referenced anywhere in
   mod-psychobot.

4. Talent/specialization API (PsychobotTalentMgr.cpp / PsychobotSpecRoles.cpp
   / PsychobotMgr.cpp - flagged as "highest risk" in the report) -
   GetPrimarySpecialization(), SetPrimarySpecialization(uint32),
   ActivateTalentGroup(ChrSpecializationEntry const*), and
   LearnTalent(uint32, int32*) returning TalentLearnResult/TALENT_LEARN_OK
   all exist in this core's Player.h with matching signatures. No changes
   needed.

5. Unit.h/Player.h "Psycho-only" symbol list (about 30 methods like
   AddComboPoints, GetArenaTeamId, EngageWithTarget, GetThreatManager,
   GetFaction, SetContestedPvP, MoveFormation, etc., flagged as missing in
   this core) - searched all 145 mod-psychobot source files for every one
   of these symbols. ZERO matches. mod-psychobot doesn't call any of them.

6. AuctionHouseBot.h difference (flagged at only 0.779 overlap) -
   PsychobotAhBot.h/.cpp is a fully standalone implementation that does
   NOT include or depend on the core's AuctionHouseBot.h at all. The
   difference is irrelevant to this module.

7. Entities/Item/ItemTemplate.h include (used by PsychobotAhBot.cpp with
   a subdirectory-style path) - file exists at the expected location in
   this core; same include pattern the core itself already relies on.

CONCLUSION: This core's "Reforged + Modernized" rework already included
the necessary mod-psychobot compatibility shims (most importantly the
11-arg WorldSession overload and the S28 bot-session hooks). Everything
else the difference report flagged turns out to live in parts of the API
mod-psychobot simply doesn't touch. Your statement that "my module is
perfect for this core" checks out.

 FIXES CARRIED OVER FROM THE PREVIOUS SESSION
===========================================================================
This zip's modules/mod-psychobot/src/PsychobotFactory.cpp/.h were the
ORIGINAL (pre-fix) versions - the 3 fixes applied last time hadn't made it
into this core yet. I re-applied all 3:

  1. GenerateOneBot() account search now starts from a cached
     _nextAccountIndex instead of rescanning accounts 1-1000 every call.

  2. GenerateOneBot() now registers the new character with
     sCharacterCache (AddCharacterCacheEntry), so bots spawned via
     ".psychobot factory spawn" can immediately be summoned/added by name
     without a server restart.

  3. PurgeAllBots() now also deletes each purged character's rows from
     ai_playerbot_db_store, ai_playerbot_random_bots, and
     ai_playerbot_guild_tasks, so purges don't leave orphaned data.

Full details of these three fixes are the same as documented previously;
see this report's earlier history if you need the line-by-line before/
after.
